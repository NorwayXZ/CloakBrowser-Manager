新界面替换旧界面之前，下面每一行都必须满足两条：

1. **已实现**：在新界面里找到对应入口，行为与旧界面一致（或按方案有意改进，并在"备注"写明）。
2. **已测试**：至少有一条自动化测试覆盖它；只能人工验证的（真实浏览器启动、WKWebView 行为、安装包），写明人工验证的日期和环境。

"现有测试"列是旧界面里覆盖这项行为的测试文件，迁移时这些断言要在新组件上重新成立。没写测试文件的，表示旧界面没有前端测试，新界面要补。

勾选方式：`[ ]` 未做，`[x]` 完成。

### 旧界面已知问题（基线截图中可见）

新界面要避免这些问题，阶段 1 起的布局检查脚本会专门检测：

- **1024 宽环境列表**：表格放不下，"操作"列被挤到可视区域外，要在表格内横向滚动才能点"打开"；名称和分组被截成"一…""美国…"（`1024/01-environments.jpg`）。
- **浏览器内核页窗口较矮时内容被裁掉**：授权说明行、授权密钥卡片、更新渠道下拉框被压扁截断，而不是让页面滚动（`1024/15-kernel.jpg`、`1280/15-kernel.jpg`）。
- **编辑页分区导航高亮不准**：停在"基础设置"时高亮的是"代理信息"（`1024/06-new-basic.jpg`）。
- 页面整体没有出现横向滚动条（`manifest.json` 中三种宽度全部为 false），问题都在容器内部。

### 截图中发现的功能问题（不属于界面重构，另行处理）

- **macOS 上"一次性身份"和"一句话建号"创建的都是 Windows 画像**：`backend/main.py` 的 `create_disposable_profile` 和 `backend/sentence_profile.py` 都固定写 `platform="windows"`，而启动前检查会拦下跨系统画像（"当前电脑是 macos，不能启动 windows 设备画像"），所以在 Mac 上用这两种方式建的环境打不开（`1280/04-preflight-dialog.jpg`）。

WebSocket 接口（VNC、CDP 代理）和 `include_in_schema=False` 的内部接口（Cookie 拉取扩展通道、浏览器起始页、指纹报告提交）不在 OpenAPI 文档里，由现有后端测试覆盖。
