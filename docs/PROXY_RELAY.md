# SOCKS5 直连与服务器中转

每个环境可以分别选择连接方式。原来的代理设置默认保持直接连接；不需要开启系统全局代理。

```text
直接连接：浏览器 → 当前 SOCKS5 → 网站
经中转：  浏览器 → 加密中转服务器 → 当前 SOCKS5 → 网站
```

最终出口由 SOCKS5 服务提供。固定出口通常保持原地址；动态代理的 IP 与会话稳定性取决于供应商，请在切换路径后检测。

## 1. 准备中转服务器

选择从使用地点能稳定连接、并且能连接供应商 SOCKS5 的服务器。美国 SOCKS5 不一定需要美国中转，应对比整条线路。

在服务器上部署有认证的加密代理入口，或在 Flux 面板创建私人代理并选择「节点自身 IP」作为出口，取得其连接链接。

支持的中转链接：

- VLESS + TLS / REALITY
- Trojan + TLS
- VMess + TLS
- Shadowsocks（加密方式不能为 none/plain）

TLS 入口需要有效证书与正确的服务器名称；新版 Xray 不支持 `allowInsecure` 跳过校验。使用 REALITY 时需保留链接中的公钥、short ID 和 server name。

如果 SOCKS5 供应商要求 IP 白名单，把中转服务器实际出网 IP 加进去。用户名中的地区、会话、IP 保持时间等参数仍保留在最终 SOCKS5 配置里。

最终 SOCKS5 地址必须能从中转服务器访问。中转模式下 `127.0.0.1` 指的是中转服务器自身，不能用它连接电脑上的本地 SOCKS5；电脑上的本地代理仍可使用直接连接方式。

## 2. 保存中转入口

在「代理 → 中转服务器」中添加名称和连接链接。可单独检测中转是否可用；这里显示的是**中转服务器的出口**，并非最终 SOCKS5 出口。

中转链接加密存储在本机数据库，不需要在中转服务器上为每条 SOCKS5 单独配置一套入口。

## 3. 按环境选择

新建或编辑环境，代理方式选「自定义代理」，类型选「SOCKS5」，填写供应商地址、端口、账号和密码。

- 「直接连接 SOCKS5」：沿用原来的线路。
- 「通过中转服务器」：再选择一个保存的中转入口。

不同环境可以共用一个中转，同时各自使用不同的 SOCKS5。启动后使用本机独立的代理运行时，不改变其他环境或系统网络。更改环境或中转配置后，关闭并重新打开相关环境才会生效。

## 4. 完整链路检测

「检查代理」使用当前选择的完整路径查询最终出口。选择中转后，还可以「对比直连与中转」，分别查看成功/失败、出口 IP 和检测耗时。

「链路握手」测量通过该路径建立目标 TLS 连接的时间，包含代理连接、认证和转发握手；「检测耗时」还包括运行时准备与出口信息查询。

耗时包含出口信息查询，不是网页测速或带宽保证。中转主要改善路由质量，不能解除最终 SOCKS5 自身的带宽限制、拥塞或服务中断；所有转发流量也会使用中转服务器的流量额度。

## 连接边界与数据迁移

- 此版本中转模式面向浏览器 TCP 访问，运行时关闭 QUIC，不提供 SOCKS5 UDP 转发。
- 目标域名交给最终 SOCKS5；连接中转域名本身可能需要本地 DNS。现有浏览器 DNS 与 WebRTC 设置继续生效，外部泄漏检测仍需实测。
- 中转不可用时不会自动回退到直连、节点自身 IP 或本地网络。需要切回时手动修改环境的连接方式。
- 正在使用的中转不能直接删除（包括回收站中的环境），先修改对应环境即可。
- 配置导出包含中转节点和环境引用；导入时会重新映射编号。完整备份继续包含数据库与加密密钥。配置备份含敏感连接信息，应妥善保管。
- 本版将数据库布局版本升至 2，原环境保持直接连接。若需降级，使用升级前的完整备份。

## 验证范围

回归测试包括配置迁移、加密存储、环境引用、接口验证、界面操作，以及真实 Xray 的本机 TLS 中转 → 认证 SOCKS5 → HTTP 响应测试。停止中转后验证没有直连回退。

这些测试证明路由与隔离行为，不代表已经验证某台商用服务器、某个 SOCKS5 供应商或所有地区的提速效果。
